# Demo corpus media assets

`demo.toml` references image files under this directory. The avatars are done
and committed. The **photos are not** — sourcing them is still an open decision
(ADR 0086 records the tradeoff). The seeder should fail loudly with the missing
path rather than silently seeding a room with no images.

## `avatars/` — 8 files, committed ✅

Square, 256×256 PNG, ~107 KiB for the set. Generated by
[`generate-avatars.mjs`](generate-avatars.mjs) — deterministic, seeded by the
output filename, so a persona's face never drifts between runs. Re-run it only
to change or add a persona; see the usage block in the script header.

| `tomas.png` | Tomás Herrera | Open Peeps |
| `space-ridgeline.png` | Ridgeline Trail Collective space | Shapes |
| `space-watershed.png` | Cascadia Watershed Council space | Shapes |

Illustrated rather than photographic on purpose: a fictional persona wearing a
real person's face is the one outcome worth avoiding outright, and it needs no
model release or takedown risk. Spaces use an abstract mark because Open Peeps
draws people and a group is not a person.

Two constraints are encoded in the generator and easy to lose if it is rewritten:

- **Faces are narrowed to a friendly-to-neutral subset.** Open Peeps' full set
  includes `rage`, `veryAngry`, `monster` and `cyclops`; unconstrained seeds land
  on them and the member list stops reading as a volunteer group.
- **Output is rasterised to PNG, not SVG.** `ratatui-image` decodes through the
  `image` crate, which has no SVG support — an SVG avatar would render in
  axon-web and be silently invisible in axon-tui.

## `photos/` — 6 files, still needed ❌

Landscape, 1600px on the long edge, JPEG. These carry the gallery and lightbox
demos, so they are the files whose realism actually matters.

| File | Subject | Role in the demo |
|---|---|---|
| `switchback-14-october.jpg` | Trail switchback, autumn | Standalone image, three weeks back |
| `party-crew.jpg` | Group of volunteers with tools | Gallery run, image 1 of 4 |
| `switchback-14-before.jpg` | Eroded trail corner | Gallery run, image 2 of 4 |
| `switchback-14-crib.jpg` | Rock cribbing under construction | Gallery run, image 3 of 4 |
| `switchback-14-after.jpg` | Rebuilt trail tread | Gallery run, image 4 of 4 |
| `talus-light.jpg` | Rocky slope, low sun | Adjacency near-miss case |

The four `switchback-14-*` / `party-crew` files are posted seconds apart by one
sender and must read as one coherent set — ADR 0081's adjacency heuristic groups
them into a single grid, and the web demo pages through them in the lightbox.
`talus-light.jpg` is deliberately posted four minutes later with a text message
between, so it must **not** join that grid; it is the standing regression case
for the grouping heuristic.

### Sourcing: still open

The avatar half of this decision is settled — generated, CC0, committed. The
photos are the half where realism is the entire point, so the same answer does
not carry over.

**CC0 photographs** look genuinely real in a gallery. Cost: fixed weight in a
repo whose history is 3.8 MB with no LFS, and each file needs a provenance row
below. Budget: **≤120 KB per file after downscaling**, so all six add under
1 MB.

**Procedurally generated images** are tiny, deterministic, and regenerable by a
script rather than stored — but they look synthetic, which undercuts a gallery
demo whose purpose is to look like a real one.

Recommended: CC0 photographs, because the gallery and lightbox scenes are the
ones a viewer judges the product by. Suggested sources are Unsplash (check the
per-photo licence — the Unsplash Licence is not CC0), Pexels, or Wikimedia
Commons filtered to CC0/public domain.
